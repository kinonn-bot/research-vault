Personal Voice Recorder (Pocket AI-style) — Android App Research

Goal: a personal Android voice-recorder app in the style of the Pocket AI product — record anywhere, get transcript + summary + action items, English-first with Mandarin bonus. Researched 2026-11-04. Sources inline at the bottom.

1. Pocket AI product reference (heypocket.com)

Pocket AI is a recording card by Open Vision Engineering (San Francisco), on sale since 2025 (~$11M raised June 2026 per TechCrunch).

  • Hardware: magnetically snaps onto phone back; 3 microphones (dual studio mics for in-person + contact mic for phone calls); ~52 g; 64 GB storage; quoted ~4 days battery; one side-button press to record, works offline, app syncs later.
  • Apps: iPhone + Android, plus web / Mac / Windows.
  • Pipeline: record → app pulls audio → cloud transcript + summary + action items; “Ask Pocket” Q&A over recordings; speaker detection; integrations (Todoist, Google Tasks, Notion, Google Drive, Linear, Asana…).
  • Pricing (US store, Oct 2026): card 129(list199). Free plan included: unlimited transcription at standard accuracy, summaries kept 30 days, 3 Ask-Pocket chats/day. Pocket Pro 239.88/yr(19.99/mo billed yearly) or $29.99/mo: highest accuracy, speaker names, live transcript, email summaries, PDF/DOCX/Markdown export, full integrations.
  • Takeaway for us: the hardware is a convenience (always-on-phone, one-press, call mic). Everything it does in software — record, transcribe, summarize, Q&A, export — is reproducible as a pure Android app. No hardware needed for v1. Main gap vs Pocket: vibration/contact call capture (Android call-recording restrictions apply — see §4).

Recommendation for this project — corrected for on-device (HF API verified 2026-11-04)

  • Server/cloud transcription: Whisper Large V3 Turbo (multilingual incl. Mandarin) or Parakeet TDT for batch throughput, via faster-whisper / NeMo on GPU. Disqualified for phone: Canary-Qwen 2.5B, Granite 8B, Whisper Large 1.55B/809M, Parakeet 1.1B, Dolphin base/small, Paraformer-large — size/RAM/battery.
  • On-device (offline) transcription — HF-verified picks (pipeline_tag= automatic-speech-recognition, sort=lastModified + downloads):
    • Default single EN+ZH model: FunAudioLLM/SenseVoiceSmall — 234M, non-autoregressive, 70ms/10s audio, 50+ langs (zh/yue/en/ja/ko). ONNX via sherpa-onnx + GGUF via handy-computer/SenseVoiceSmall-gguf (33k dl) / FunAudioLLM/SenseVoiceSmall-GGUF. HF downloads ~25.5k last month. Licence: license:other → FunASR MODEL_LICENSE (commercial use with attribution per maintainers — read MODEL_LICENSE §2.2 before shipping).
    • Cleanest-licence single EN+ZH model: openai/whisper-small (242M params, HF reports apache-2.0) or openai/whisper-base (72M params, HF reports apache-2.0) as sherpa-onnx ONNX int8. HF downloads: small 4.24M, base 3.59M. Larger/slower than SenseVoice, best ecosystem.
    • Smallest footprint: moonshine-ai/moonshine-tiny-zh (27M, CER 13.7% FLEURS-zh, Q8 GGUF 34MB via handy-computer/moonshine-tiny-zh-gguf) + EN twin UsefulSensors/moonshine-tiny (27M, Q8 34MB, MIT per OpenASR repack). Caveat: two models, no code-switch in one sentence; HF card says license:other on tiny-zh — verify upstream MIT claim before shipping.
  • Mandarin strategy: single multilingual model (Whisper Turbo / SenseVoice / Dolphin) beats juggling separate EN + ZH models — important for Singapore code-switching (English ↔ Mandarin in one sentence). Test shortlisted models on code-switched audio before committing.

3. Android on-device STT feasibility

  • sherpa-onnx (k2-fsa, actively maintained — v2.0.1 Oct 2026): the pragmatic choice. ONNX Runtime, fully offline, first-class Android (+ iOS/HarmonyOS) support with Java/Kotlin APIs; ships Whisper, Paraformer, SenseVoice, Zipformer model builds plus VAD, speaker diarization, punctuation, TTS. Precedent apps exist (offline captioning, voice-typing apps bundling Whisper-base via sherpa-onnx).
  • whisper.cpp: C/C++ via JNI, quantized GGUF models run on mid-range phones (base/small real-time-ish on CPU; large needs flagship or server). Larger integration effort than sherpa-onnx but biggest community.
  • Moonshine: designed for edge; worth a look if live-caption latency becomes the goal.
  • Plan: bundle one small model in-APK (e.g. Whisper base/small-int8 or SenseVoice-Small ONNX, tens-to-low-hundreds MB — consider Play Asset Delivery / download-on-first-run), transcribe on-device by default, offer server-side Turbo re-transcription as a “high accuracy” option. Chunked inference (10–30 s windows + VAD) keeps memory flat.

4. Android app architecture (v1 outline)

UI (Jetpack Compose, MVI/MVVM)
 │  Recordings list · Player · Transcript view · Summary/Actions · Ask (chat) · Settings
 ▼
ForegroundService recorder (AudioRecord/AAudio → WAV/FLAC/Opus, MediaStore + Room index)
 │  + VAD-based segmentation (sherpa-onnx Silero VAD)
 ▼
Transcription worker (WorkManager) — on-device sherpa-onnx first, server fallback queue
 ▼
Post-processing — punctuation restore, diarization (Pro-tier?), language ID (en/zh)
 ▼
LLM layer — summary + action items + Ask Q&A (cloud API with user key in v1;
           on-device small LLM later). Never train on user audio.
 ▼
Export/share — TXT/MD/PDF, integrations (Google Tasks/Drive, Todoist…)
  • Key Android specifics: Foreground Service with microphone foreground-service type (+ persistent notification); RECORD_AUDIO runtime permission; battery-optimisation exemption prompt for long recordings; Scoped Storage via MediaStore; Room for metadata; WorkManager for deferred upload/transcription; Hilt + Coroutines/Flow; minSdk 29–31 (covers sherpa-onnx Android 11+ precedent).
  • Call recording: Android restricts direct call audio on modern versions (privacy/PDPA); Pocket’s contact-mic trick is hardware. v1 should target mic/in-person recording + speakerphone-with-consent, and document Singapore PDPA consent expectations.
  • Privacy posture (differentiator vs Pocket/PLAUD): default offline transcription, user-held API keys, no training on recordings, export-and-delete. Pocket processes in the US cloud; local-first is our edge.
  • Testing priorities: code-switched EN/ZH accuracy, battery drain on 2-h recordings, low-end device (e.g. 4 GB RAM) transcription latency, consent UX for shared recordings.

5. Suggested build order

  1. Recorder service + playback + local storage (usable voice memo, no AI).
  2. On-device transcription via sherpa-onnx (bundled small model, EN+ZH).
  3. Cloud LLM summaries/action items + Ask (BYO API key).
  4. Server-side high-accuracy re-transcription option.
  5. Diarization, live transcript, export formats, integrations.
